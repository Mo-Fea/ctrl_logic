# route.py 使用说明

这个文件用来帮助别人快速理解 `route.py` 的作用、运行流程，以及它生成的机器人动作矩阵。

## 1. route.py 是做什么的

`route.py` 的主要作用是：

```text
识别二维码
解析 KFS 摆放信息
调用 meilin.py 规划路线
把路线转换成机器人可以按顺序执行的动作矩阵
显示路线可视化图
```

简单说，`route.py` 是从“二维码信息”到“机器人动作表”的转换入口。

## 2. 相关文件

| 文件 | 作用 |
| --- | --- |
| `route.py` | 摄像头识别二维码，生成路径和动作矩阵 |
| `meilin.py` | 梅林路径规划规则和最短路径搜索 |
| `action_matrix.md` | 动作矩阵的详细定义 |
| `a.py` | 原始版本的 `route.py` 备份 |

## 3. 二维码内容格式

二维码内容应是一个 12 位字符串。

每一位对应梅林里的一个格子：

```text
第1位  -> 1号格
第2位  -> 2号格
...
第12位 -> 12号格
```

每个字符含义如下：

| 字符 | 含义 |
| --- | --- |
| `0` | 空格 |
| `1` | R1-KFS |
| `2` | R2-KFS |
| `3` | 假 KFS，也就是 low |

例如：

```text
000020020200
```

表示：

```text
5号格是 R2-KFS
8号格是 R2-KFS
11号格是 R2-KFS
其他位置为空
```

解析二维码的函数是：

```python
qr_to_kfs(qr_string)
```

它会把 12 位字符串转换成 `meilin.py` 能识别的 `kfs` 字典。

## 4. route.py 的运行流程

主流程在 `main()` 里。

执行顺序大致是：

```text
1. 打开 D435i 摄像头
2. 循环读取彩色画面
3. 使用 OpenCV 识别二维码
4. 如果识别到 12 位二维码字符串，就解析成 kfs
5. 调用 meilin.plan_path(kfs) 生成路径
6. 调用 path_to_action_matrix(kfs, path) 生成动作矩阵
7. 打印路径、动作矩阵、动作说明
8. 调用 meilin.visualize(kfs, path) 显示可视化路线图
```

## 5. meilin.py 返回的路径格式

`meilin.plan_path(kfs)` 返回的 `path` 里有两种内容。

第一种是整数：

```python
2
5
8
```

表示机器人实际走到某个格子。

第二种是元组：

```python
(5, "reach", 4)
```

表示机器人在 5 号格，不走到 4 号格，只是在旁边夹取 4 号格的 R2-KFS。

## 6. 动作矩阵是什么

`route.py` 会把 `meilin.py` 的路径转换成动作矩阵。

动作矩阵是 `n*5`：

```text
一行 = 机器人要执行的一个动作
五列 = 这个动作的具体信息
```

每一行格式如下：

```text
[from_pos, to_pos, move_dir, height_action, grab_action]
```

五列含义如下：

| 列名 | 含义 |
| --- | --- |
| `from_pos` | 动作开始时机器人在哪个格子 |
| `to_pos` | 这个动作面对的目标格子 |
| `move_dir` | 方向 |
| `height_action` | 是否上下台阶 |
| `grab_action` | 是否夹取 |

## 7. move_dir 编码

| 编码 | 含义 |
| --- | --- |
| `0` | 原地 |
| `1` | 前方 |
| `2` | +90度方向（左边） |
| `3` | -90度方向（右边） |
| `4` | 180度方向（后方） |

如果这一行是夹取动作，`move_dir` 表示夹爪应该朝哪个方向伸出去。.

## 8. height_action 编码

| 编码 | 含义 |
| --- | --- |
| `0` | 不上下台阶 |
| `1` | 上台阶 |
| `2` | 下台阶 |

抓取动作一般是 `0`，因为机器人身体不移动。

## 9. grab_action 编码

| 编码 | 含义 |
| --- | --- |
| `0` | 不夹取 |
| `1` | 行进前抓目标格 R2 |
| `2` | 旁夹 R2 |
| `3` | R1 协助移除 |

## 10. 重要先后逻辑

如果机器人要走到某个格子，并且这个格子上有 R2-KFS，机器人不能直接踩上去。

所以 `route.py` 会把这个动作拆成两行：

```text
先抓目标格 R2
再走到目标格
```

例如机器人要从 2 号格走到 5 号格，并且 5 号格有 R2-KFS：

```text
[2, 5, 1, 0, 1]
[2, 5, 1, 1, 0]
```

第一行表示：

```text
机器人在 2 号格
面向 5 号格
先夹走 5 号格的 R2-KFS
机器人身体不移动
```

第二行表示：

```text
5 号格已经清空
机器人从 2 号格走到 5 号格
方向向前
执行上台阶
不夹取
```

## 11. 示例输出

假设规划路径是：

```text
2 -> 5 -> 8 -> 11 -> 12
```

并且 5 号格、8 号格有 R2-KFS，那么动作矩阵可能是：

```text
[[ 2  5  1  0  1]
 [ 2  5  1  1  0]
 [ 5  8  1  0  1]
 [ 5  8  1  1  0]
 [ 8 11  1  2  0]
 [11 12  3  2  0]]
```

逐行解释：

| 行 | 含义 |
| --- | --- |
| 1 | 在 2 号格，面向 5 号格，先夹走 5 号格 R2 |
| 2 | 从 2 号格走到 5 号格，上台阶 |
| 3 | 在 5 号格，面向 8 号格，先夹走 8 号格 R2 |
| 4 | 从 5 号格走到 8 号格，上台阶 |
| 5 | 从 8 号格走到 11 号格，下台阶 |
| 6 | 从 11 号格走到 12 号格，下台阶 |

## 12. 如何运行

确保 D435i 摄像头已连接，并且安装了依赖：

```text
opencv-python
numpy
matplotlib
pyrealsense2
```

运行：

```bash
python3 route.py
```

程序启动后，把二维码对准摄像头。

识别成功后，终端会打印：

```text
检测到二维码
规划路径
机器人动作矩阵
动作序列说明
```

同时会弹出梅林路径可视化图。

按 `q` 可以退出程序。

## 13. 常见问题

### 摄像头打不开

可能原因：

```text
D435i 没有连接
pyrealsense2 没安装
摄像头正在被其他程序占用
```

### 识别不到二维码

可以检查：

```text
二维码是否清晰
二维码内容是否正好是 12 位
光照是否太暗或反光
摄像头是否对焦
```

### 找不到路径

说明当前 KFS 摆放下，`meilin.py` 没有找到满足规则的可行路径。

这通常和以下规则有关：

```text
R2 必须从 2 号格进入
R2 必须从 10 或 12 号格出去
R2 只能拿 2 个 R2-KFS
R2 不能碰假 KFS
相邻台阶高度差必须为 20
```

## 14. 一句话总结

`route.py` 做的事情就是：

```text
二维码 -> KFS布局 -> 梅林路径 -> 机器人动作矩阵
```

最终机器人只需要按照动作矩阵从上到下执行即可。
