# ArUco 双码三维坐标检测

这个项目使用 Intel RealSense 深度相机检测画面中的两个 ArUco 码，获取它们在相机坐标系下的三维坐标，并计算从左码指向右码的向量、向量长度和单位向量。

## 文件

- `ar.py`：当前主程序，包含屏幕显示场景下的识别增强。
- `ar1.py`：未加入屏幕识别增强前的版本，保留双码坐标和向量输出逻辑。

## 运行环境

需要安装：

```bash
python3
opencv-contrib-python
pyrealsense2
numpy
```

其中 ArUco 模块来自 `opencv-contrib-python`，普通 `opencv-python` 可能没有 `cv2.aruco`。

## 运行

连接 RealSense 相机后，在项目目录运行：

```bash
python3 ar.py
```

程序会打开一个窗口：

```text
ArUco Detection
```

按 `q` 退出程序。

## 功能说明

`ar.py` 会执行以下流程：

1. 启动 RealSense 彩色流和深度流。
2. 将深度图对齐到彩色图。
3. 检测 `DICT_4X4_50` 类型的 ArUco 码。
4. 获取每个码中心点附近的深度中值。
5. 使用 RealSense 内参将像素点和深度反投影为三维坐标。
6. 按画面中的左右位置选出左码和右码。
7. 计算：

```text
向量 V = 右码坐标 - 左码坐标
向量长度 length
单位向量 unit_V
```

## 输出含义

终端输出示例：

```text
左码 ID 1 坐标: x=-0.120m, y=0.030m, z=0.650m | 右码 ID 2 坐标: x=0.110m, y=0.028m, z=0.648m | 向量 V=右码-左码: vx=0.230m, vy=-0.002m, vz=-0.002m | 向量长度 length=0.230m | 单位向量 unit_V=(1.000, -0.009, -0.009)
```

坐标单位是米，坐标系是 RealSense 相机坐标系：

- `x`：左右方向
- `y`：上下方向
- `z`：相机正前方深度方向

所以相机到屏幕/码中心点的大致距离主要看 `z`。

## 屏幕识别增强

因为 ArUco 码显示在屏幕上时容易过亮，`ar.py` 做了几项增强：

- 优先尝试彩色流 `1280x720`，原本是 `640x480`。
- 如果高分辨率拿不到帧，会自动回退到 `640x480`。
- 关闭彩色相机自动曝光，并设置较低曝光和增益，减少屏幕发白。
- 放宽 ArUco 检测参数，让较小的远距离码更容易被检测。
- 检测失败时尝试使用 CLAHE 对比度增强图和轻微压暗图再次检测。

程序退出时会自动恢复彩色相机自动曝光，避免影响之后其他软件使用相机。

## 常见问题

### Frame didn't arrive within 5000

如果高分辨率模式下相机拿不到帧，程序会自动回退到 `640x480`。如果两个配置都失败，检查：

- 相机是否被其他程序占用
- USB 线和接口是否稳定
- RealSense 是否正常连接

### 画面很暗

这是为了避免屏幕过曝而设置了手动曝光。正常按 `q` 退出时程序会恢复自动曝光。如果异常退出后画面仍然偏暗，可以重新插拔相机恢复。

### 一米多识别不稳定

常见原因是 ArUco 码在画面中的像素太小。代码已经做了增强，但如果码边长只有二三十像素，仍然可能不稳定。尽量让码在画面中占更大的像素面积，或者保持相机对焦和画面稳定。
